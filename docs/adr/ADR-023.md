# ADR-023: API & WebSocket Diagnostic Tooling

## Status

Proposed

## Date

2026-08-13

## Council

Pendiente de aprobación (Engineering Council review required — TASK governance registrado)

---

## 1. Context

El Bridge Baileys usa WebSockets reales y existe una necesidad concreta de diagnosticar conexión, handshake, `ws-token`, flujo de sesión y comportamiento del bridge con independencia de la UI. Además, MIA debe disponer de una forma reproducible y versionable de probar sus APIs sin depender exclusivamente de la UI ni de la configuración local de un desarrollador.

Principio: **problema real → capacidad necesaria → herramienta mínima → contrato reproducible.** No adoptar múltiples clientes API redundantes (HTTPie/Postman/Insomnia quedan fuera).

## 2. Decision

- **wscat**: herramienta mínima de diagnóstico WebSocket externo del bridge. Aprobado conceptualmente.
- **Bruno**: herramienta primaria de pruebas API manuales/reproducibles, **condicionada** a que las colecciones sean versionables y pertenezcan al repositorio (`bruno/`), no a la config local de un desarrollador.
- No se adoptan otras herramientas WebSocket ni clientes API adicionales.

## 3. Evidence

**WebSocket real confirmado** — `services/whatsapp-bridge/src/server.ts:150`:
`new WebSocketServer({ server, path: '/v1/ws' })` (dependencia `ws ^8.18.0` en `services/whatsapp-bridge/package.json`).

**Autenticación del WS** — `server.ts:152-160`: query params `businessId` + `token`; token = HMAC-SHA256 base64url del `WHATSAPP_BRIDGE_SECRET` sobre `businessId`; rechazo con `ws.close(4401, 'Unauthorized')`. El token se obtiene de `GET /api/channels/baileys/ws-token` → `{ token, wsUrl: "wss://<bridge>/v1/ws", businessId }` (`src/app/api/channels/baileys/ws-token/route.ts`).

**Uso wscat canónico**:
```
wscat -c "wss://<bridge>/v1/ws?businessId=<id>&token=<signed>"
```

**Endpoints candidatos iniciales para Bruno** (81 rutas en `src/app/api`):
- `GET /api/system/health`
- `GET /api/channels/connections`
- `GET /api/channels/baileys/ws-token`
- `GET /api/channels/baileys/session`
- `POST /api/channels/baileys/followup`
- `POST /api/channels/baileys/reconnect`
- `POST /api/channels/baileys/webhook`
- `POST /api/channels/webhook/[channel]`

**Autenticación de la app**: las rutas usan cliente Supabase server con cookie de sesión (`supabase.auth.getUser()`); el token de WS valida además ownership del negocio.

## 4. Scope

- Documentar el comando wscat canónico de diagnóstico del bridge.
- Crear colección Bruno inicial (salud + canales) versionada en `bruno/` del repo.
- Plantilla de entorno Bruno con `{{env.VAR}}`, sin secretos.
- Formalizar en este ADR.

## 5. Non-goals

- No instalar wscat/Bruno ni crear colecciones todavía (esta decisión se somete al Council antes de ejecutar).
- No HTTPie/Postman/Insomnia adicionales.
- No modificar producto ni bridge.

## 6. Files affected

`bruno/` (colecciones `.bru` + entornos), `bruno/environments/*.local.bru` (gitignored, con valores reales), `.gitignore` (entrada para env local Bruno), `docs/adr/ADR-023.md`, doc de diagnóstico wscat.

## 7. Risks

- Colección versionada con secretos → prohibido por secret scan de governance/Subaru.
- Endpoints auth-dependientes no testables sin sesión → la colección debe separar endpoints públicos de los que requieren cookie.
- Dependencia de una sola máquina → mitigada por repo-ownership desde el día 1.

## 8. Gates

- Secret scan (governance/Subaru) sobre los `.bru`.
- Revisión de que ningún `.bru` contenga valores reales (solo `{{env.VAR}}`).
- Lint/build intactos (solo se añaden archivos Bruno y docs).

## 9. Dependencies

Aprobación del Engineering Council. Independiente de ADR-022.

## 10. Acceptance criteria

- `bruno/` en el repo con colección ejecutable contra variables de entorno, 0 secretos.
- Comando wscat documentado y reproducible contra el bridge (staging).
- ADR-023 aprobado por el Council.

## 11. Consequences

- Diagnóstico WebSocket del bridge sin depender de la UI.
- Pruebas API reproducibles por cualquier miembro del equipo en cualquier máquina (Linux/Windows).
- Materializa el principio de contrato reproducible para testing manual.
