# ADR-022: Environment Runtime Normalization

## Status

Accepted

## Date

2026-08-13

## Council

Aprobado por el Engineering Council (TASK-20260813-063009431, 7/7) — 2026-08-13. Integración de la base (`.nvmrc`, `engines`, `engine-strict`, CI 20→22) verificada bajo Node v22.23.2.

---

## 1. Context

MIA no declara de forma única su runtime soportado. Cuatro entornos operan hoy con versiones divergentes:

| Entorno | Node |
|---------|------|
| Máquina local (HP / Linux) | 26.7.0 |
| CI (`ci.yml`) | 20 |
| Validate / Council-audit / Docs-generate | 22 |
| Docker bridge (`services/whatsapp-bridge/Dockerfile`) | 22 (node:22-slim) |

`package.json` raíz no declara `engines`; no existe `.nvmrc` ni `.node-version`. La auditoría de compatibilidad de entornos identificó como prioridad fijar un runtime común antes de adoptar herramientas de gestión de Node (fnm/nvm/Volta).

## 2. Decision

Declarar **Node 22 (LTS Jod)** como runtime contractual de MIA, con un **único archivo canónico `.nvmrc`** con valor `22`. Complementariamente, declarar `engines.node` en `package.json` (consumido por npm) y en `services/whatsapp-bridge/package.json`. Alinear CI/validate/Docker al contrato. La herramienta de gestión de Node (fnm) es una consecuencia del contrato, no el contrato; se evalúa después.

**Fuente única de versión**: `.nvmrc` es suficiente (leído por nvm, fnm y `actions/setup-node --node-version-file`). `.node-version` es duplicación sin consumidor distinto; solo se añadiría si se adoptara asdf/mise (fuera de alcance). `engines` en `package.json` no es duplicación: lo consume npm, no el version manager — son complementarios.

## 3. Evidence

Validación ejecutada bajo **Node v22.23.2 + npm 10.9.8** (binario oficial; paridad con `actions/setup-node@v4` node 22 = última 22.x LTS, 2026-07-28):

| Validación | Resultado |
|-----------|-----------|
| `npm ci` | Pass (768 paquetes; 8 vulns preexistentes) |
| `npm run lint` | Pass |
| `npm run test:unit` | Pass — 576/576 (locale en_US / CI) |
| `npm run build` (Next 16) | Pass |
| Workshop tests (basic-flow, council-flow) | Pass ambos |

**Hallazgo (preexistente, no bloquea)**: `tests/component/usage-bar.test.tsx:17` falla bajo locale `es_ES` tanto en Node 22 como en Node 26 (`12.000` vs esperado `12,000`); pasa con `en_US` (locale de CI). Es un test sensible a locale, no una incompatibilidad de Node 22. Issue conocido del patrón `toLocaleString()` sin locale explícito.

**E2E no ejecutado** localmente: requiere instalación de browsers y credenciales reales; además `validate.yml` (workflow Node 22) no corre e2e — solo `ci.yml` (Node 20) lo ejecuta.

## 4. Scope

- Crear `.nvmrc` = `22`.
- Añadir `engines.node` en `package.json` raíz y alinear el de `services/whatsapp-bridge/package.json` (`>=18` → contrato 22).
- Alinear `ci.yml` (5 jobs: node 20 → 22). `validate.yml`/`council-audit.yml`/`docs-generate.yml` ya en 22: solo verificar.
- Verificar Dockerfile del bridge (ya `node:22-slim`), sin cambios.
- Assert de versión en `scripts/environment-check.script.ts`.
- Documentar onboarding Linux/Windows (`start.sh`/`start.bat`).
- Formalizar en este ADR.

## 5. Non-goals

- No instalar fnm/nvm/Volta (se evalúa después, como consecuencia del contrato).
- No corregir el test de UsageBar (issue de locale, separado).
- No modificar producto, Fly.io, Vercel, Supabase.

## 6. Files affected

`.nvmrc` (nuevo), `package.json` (engines), `services/whatsapp-bridge/package.json` (engines), `.github/workflows/ci.yml`, `scripts/environment-check.script.ts`, `start.sh`, `start.bat`, docs onboarding, `docs/adr/ADR-022.md`.

## 7. Risks

- Node 26 local deja de ser el runtime de referencia; builds locales podrían ocultar incompatibilidades que el contrato 22 detecta. Mitigación: viabilidad demostrada con 22.
- `engines` solo advierte, no bloquea; requiere disciplina (o `engine-strict` opcional).
- npm 12 (local) vs npm 10 (bundled con Node 22): resolver el paquete de npm del contrato.

## 8. Gates

`lint` + `build` + `test:unit` + workshop tests en 22 (ya pasados; re-ejecutar en ejecución), 1 build completo de CI tras el bump, `environment-check`/`doctor`, e2e de CI movida a 22.

## 9. Dependencies

Aprobación del Engineering Council. Independiente de ADR-023.

## 10. Acceptance criteria

- `.nvmrc` = `22` presente y consumido por CI (`node-version-file`).
- `engines.node` en ambos package.json.
- Los 4 entornos operan en 22.x.
- CI verde completo (incl. e2e) con Node 22.

## 11. Consequences

- Runtime único y reproducible en Linux y Windows.
- Base para evaluar fnm como gestor recomendado.
- Exige alinear la maquina local (HP Linux) de Node 26 → 22.
